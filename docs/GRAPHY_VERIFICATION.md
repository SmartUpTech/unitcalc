# Graphy implementation and verification

Base: `release/v11` (`6b4fa66bd076`). Working branch: `codex/graphy-standardization`.

## Delivered
- One semantic definition and renderer for the basic calculator and all existing unit/currency converters.
- One app-theme color resolver for Compose and Canvas, canonical resource dimensions/shapes/font,
  flat cards, compact operation pills, quiet captions and emphasized result nodes.
- Dependency-based layout with inputs near their consumers; narrow graphs wrap vertically.
  No whole-graph shrinking, arbitrary converter branch layouts or duplicate result card.
- Node selection through touch, keyboard and TalkBack; common Compose details and progressive formula disclosure.
- Immutable conversion snapshots and linear, affine, rate, reciprocal, composite and direct metadata.
  Correct temperature/offset explanations, reversed conversions, reciprocal fuel explanations,
  explicit Gas Mark piecewise semantics and currency cache notices/identity/timestamps.
- Authoritative formatted results, shared calculator intermediate formatting, unit coefficient separators
  matching settings, and scientific notation for tiny/large factors. Computed percentages preserve their inputs.
- Invalid graphs/results clear stale content. Lazy Graphy tabs receive the current snapshot.
- Existing Views are reused; unchanged output/configuration skips layout reconstruction; output collections are frozen once.
- Obsolete string-inferred operations, arbitrary related-unit branches, duplicate Compose tokens,
  fixed graph palette and unused TextView styles removed after checking callers.

`Conversions.java` and `ExpressionEvaluator.java` are unchanged. History, favorites, rate fetching,
unit registry rules and valid-result rounding are unchanged. The selected conversion now receives
one focused explanation instead of four arbitrary additional conversions.

## Visual evidence and limits
Native Android renderer previews are generated by `GraphyRenderingTest` in
`app/build/reports/graphy/`. Percentage, multi-step expression, length, temperature, currency and
data all use the same renderer and tokens. Light/dark and Purple Mountain Majesty previews were
reviewed directly; their input/result/operation hierarchy and connector language match.

Examples:
- [Light percentage](../app/build/reports/graphy/porcelain_white-percentage.png)
- [Light multi-step](../app/build/reports/graphy/porcelain_white-multi-step.png)
- [Dark length](../app/build/reports/graphy/graphite_black-length.png)
- [Light temperature](../app/build/reports/graphy/porcelain_white-temperature.png)
- [Purple currency](../app/build/reports/graphy/purple_mountain_majesty-currency.png)
- [Dark data](../app/build/reports/graphy/graphite_black-data.png)

These are production-renderer previews with representative fixtures, not full device screenshots.
No emulator/device is attached (no KVM). Full workspace navigation/swaps, Compose dialogs,
TalkBack gestures, rotation/recreation and large-font scrolling remain device QA tasks.
No performance profiler was available; allocation/layout improvements were reviewed and exercised,
not benchmarked.

EMI, GST, SIP, Compound Interest, BMI, geometry/age calculators and chart implementations do not
exist in this v11 catalog. They were not added during this visual refactor. Chart/gauge/timeline/
comparison primitives should be introduced with real semantic data requirements through the
common engine. Gas Mark is explicitly explained as a piecewise direct mapping; its conditional
branches are not expanded into individual arithmetic nodes. Currency time is the existing recorded
cache-fetch time, not a guaranteed provider quote timestamp; freshness/fetch policy is preserved.

## Currency build configuration
Currency provider keys are supplied through untracked `local.properties`, Gradle properties
or CI environment variables named `CURRENCY_RATE_KEY_1` through `CURRENCY_RATE_KEY_4`.
The local build retains its existing configured keys. Other builds must provide their keys
for authenticated live rate fetching; cached rates and the existing keyless fallback remain
available. No embedded credentials are included in the proposed file contents.
